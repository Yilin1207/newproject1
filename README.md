# Наш район

**Текущий этап: фронтенд-демо на Next.js + Tailwind CSS.**

Готовы три страницы: главная (`/`), игровая комната (`/lobby`) и профиль (`/profile`).
В лобби работают выбор персонажа, готовность и короткая подготовка района с разными итогами.
Имя, настройки, текущая комната и история сохраняются в localStorage этого браузера.
Для проверки входа по коду используйте **DEMO26**.

Это локальное демо интерфейса: без сервера, регистрации, сетевой игры и 3D.
Остальные требования ниже описывают будущую полную версию.

Сценарий показа и разделение задач: [docs/DEMO.md](docs/DEMO.md).

«Наш район» — кооперативная браузерная 3D-игра для 2–4 игроков.
Проект разрабатывается по предмету «Фронтенд и бэкенд разработка».

## О проекте

Игроки оказываются в небольшом районе, которому угрожает сильная
гроза. До её наступления необходимо собрать припасы, подготовить
здания и распределить ограниченные ресурсы.

Участники выполняют общую задачу, но у каждого есть личная цель.
Поэтому игрокам приходится договариваться и выбирать между
собственными интересами и пользой для района.

Цель разработки — создать работающую многопользовательскую игру
с клиентской частью, сервером и базой данных.

## Игровой процесс

1. Пользователь регистрируется или входит в аккаунт.
2. Создаёт комнату или подключается по коду.
3. Выбирает персонажа и подтверждает готовность.
4. После запуска получает общую задачу и личную цель.
5. Исследует район и взаимодействует с предметами.
6. Вместе с другими игроками готовится к грозе.
7. После завершения получает результаты партии.

Одна партия рассчитана примерно на 10–15 минут.

Пример выбора: в районе есть один аккумулятор, который нужен
магазину и общему убежищу. Игроки решают, какое здание получит
электричество. Этот выбор влияет на состояние района и концовку.

## Планируемые возможности

### Аккаунт

- Регистрация, вход и выход.
- Профиль пользователя.
- Выбор персонажа из готовых вариантов.
- Просмотр истории завершённых партий.

### Совместная игра

- Комнаты на 2–4 человека.
- Подключение по коду.
- Отображение участников и их готовности.
- Синхронизация перемещения и действий.
- Уведомления о подключении и отключении игроков.

### Игровой мир

- Небольшая трёхмерная карта района.
- Камера от третьего лица.
- Ходьба, бег и прыжок.
- Подбор, перенос и бросок предметов.
- Сбор припасов и установка аккумулятора.
- Общие задания и личные цели.
- Гроза и визуальные последствия решений.
- Несколько результатов прохождения.

### Настройки

- Громкость звука.
- Чувствительность мыши.
- Качество графики.

## Карта

В первую версию входят пять основных мест:

| Место | Назначение |
|---|---|
| Общий дом | Начальная точка и место хранения припасов |
| Магазин | Объект, которому требуется электричество |
| Площадка с генератором | Место работы с оборудованием |
| Площадь | Центральная часть района |
| Мост | Участок, который необходимо подготовить к грозе |

Визуальное направление — стилизованное окружение
и аниме-персонажи. Используются собственные или готовые
ассеты с подходящими лицензиями.

## Архитектура

Проект состоит из трёх основных частей.

**Клиент** отображает страницы приложения и игровой мир,
обрабатывает управление и отправляет действия пользователя
на сервер.

**Сервер** управляет комнатами, проверяет игровые действия,
синхронизирует участников и определяет результаты партии.

**База данных** хранит пользователей, сведения о партиях
и результаты участников.

Регистрация, профиль и история партий работают через HTTP API.
Перемещения игроков и изменения игрового мира передаются
через Socket.IO.

Сервер является источником общего игрового состояния.
Например, он проверяет, свободен ли предмет и может ли игрок
его подобрать. Это исключает одновременное владение одним
предметом несколькими участниками.

## Основные данные

- Пользователь: имя, email, хеш пароля, дата регистрации.
- Комната: код, создатель, участники, статус.
- Партия: сценарий, время начала и завершения, общий результат.
- Результат игрока: личная цель и её выполнение.
- Событие: значимое действие и время его выполнения.

Пароли хранятся в виде хешей. Личные цели доступны только
соответствующим игрокам.

## Команда

| Участник | Ответственность |
|---|---|
| Акжол | Интерфейс: главная, лобби, адаптивная вёрстка, выбор персонажа и визуальные компоненты |
| Ерасыл | Логика фронтенда: профиль, локальное состояние, сценарий подготовки, результаты, интеграция и проверки. Сервер — на следующем этапе |

Интеграция частей проекта и проверка совместной игры
выполняются всей командой.

## Этапы разработки

1. Согласование требований и структуры данных.
2. Подготовка клиентского и серверного приложений.
3. Регистрация, авторизация и игровые комнаты.
4. Создание карты и управления персонажем.
5. Подключение совместной игры.
6. Реализация заданий, грозы и результатов.
7. Проверка, оптимизация и подготовка демонстрации.

## Проверка проекта

Перед сдачей необходимо проверить:

- вход и регистрацию с корректными и ошибочными данными;
- подключение двух пользователей к одной комнате;
- синхронизацию персонажей и предметов;
- невозможность подобрать один предмет одновременно;
- выполнение заданий и влияние решений на результат;
- завершение партии и сохранение результатов;
- поведение при отключении участника;
- производительность во время обычной погоды и грозы.

## Ожидаемый результат

Несколько игроков с разных компьютеров подключаются к одной
комнате, видят действия друг друга и проходят общий сценарий.

Их решения влияют на концовку. После завершения результаты
сохраняются и доступны в профиле.

## Статус проекта

Готово локальное демо фронтенда с тремя страницами.
Полная сетевая игра остаётся следующим этапом.

Для запуска демо не нужны переменные окружения, база данных или отдельный сервер.

## Запуск фронтенда

Требуется Node.js 20.9 или новее и npm.

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

## Команды

- `npm run dev` — сервер разработки.
- `npm run build` — сборка для production.
- `npm start` — запуск production-сборки (после `npm run build`).
- `npm run lint` — проверка ESLint.
- `npm run typecheck` — генерация типов маршрутов и проверка TypeScript.

## Структура фронтенда

- `src/app/page.tsx` — главная страница.
- `src/app/lobby/page.tsx` — лобби, выбор героя, подготовка и результат.
- `src/app/profile/page.tsx` — профиль, настройки и история.
- `src/components/` — навигация, диалоги, аватары и SVG-иллюстрация.
- `src/lib/demo-store.ts` — локальное состояние и сохранение данных.
- `postcss.config.mjs` — подключение Tailwind CSS 4.
- `src/app/layout.tsx` — общий макет и метаданные.
- `src/app/globals.css` — глобальные стили.
- `next.config.ts` — настройки Next.js.

Используется App Router. Алиас `@/*` указывает на `src/*`.
Сервер и 3D не входят в текущий этап. Зависимости для них в демо не используются.
